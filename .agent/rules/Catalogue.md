# catalogue.md
Job: approved product data, variants, colours and the static guide.

- Publish only owner-approved product data. Never invent specifications, coverage, colours or certifications. Never show draft products publicly. Why: a false specification is a customer-facing and possibly legal error.
- Seed the catalogue only from the approved list the owner supplies (G9). Why: guessed products mislead customers.
- Let staff create, edit, preview, publish and archive products. Let customers search by name and filter by category, surface, indoor or outdoor use and finish. Why: staff need control, and customers need to narrow a long list.
- Give each product a name, unique slug, description, category, surfaces, use, preparation, recommended coats, coverage with its basis, drying and recoating guidance, images and approved documents. Why: the guide and calculator read these fields.
- Build variants only from approved compatible options (finish, colour, pack), each with a unique SKU. Never generate every possible combination. Why: most combinations do not exist.
- Show each variant's price state, availability and lead time from its record, and block invalid combinations. Word the lead time as enquiry-and-communications.md requires. Why: what customers see must match what can be quoted.
- Show approved colour names, codes and swatches linked to compatible products. Show the name and code beside every swatch. Why: a swatch alone fails colour-blind users and screens differ.
- Show the screen-variation note and the no-formal-colour-confirmation note on every colour page and every product page with a colour choice. Store the no-refund-on-colour sentence as policy text under G4. Why: the owner confirmed the wording, but nobody has tested whether it is enforceable.
- Build the static guide from the same approved fields. Link to products. Show a contact prompt when nothing fits. Why: a guide that invents a fit is worse than none.
- Required tests: only valid variants can be requested. A guide with no match shows the contact prompt. Draft products are absent from public routes. No placeholder SKUs exist. Why: these prove the rules above hold.
